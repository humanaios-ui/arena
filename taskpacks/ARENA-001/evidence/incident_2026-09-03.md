# Riverstone incident note — 2026-09-03

## Impact

For 17 minutes, completion latency rose sharply and some jobs remained queued longer than expected.

## Initial hypothesis

Database saturation was suspected because application logs contained several slow PostgreSQL writes during the incident window.

## Counter-evidence

The database CPU graph remained below 55%, but the connection-pool saturation metric was unavailable due to a monitoring gap. Separately, worker logs show repeated queue-lease expirations beginning two minutes before the first slow database write.

## Status

Root cause remains **unresolved**. The available evidence does not establish whether database pressure, queue-lease behavior, or another upstream condition was causal.
